# 04, Base de Conocimiento

## Objetivo

Ordenar lo que el usuario trae: que sabemos, que no sabemos y que queremos aprender.

## Notas del método

- Preservar totalidad del contenido relevante.
- Separar hechos, opiniones, hipotesis y supuestos.
- No convertir material crudo en insights cerrados.
- Mantener redundancias si aportan trazabilidad.
- Permitir contradicciones.

## Documentos a tocar

- `descubrimiento/base-conocimiento.md`
- `descubrimiento/assumptions.md`
- `descubrimiento/documento-discovery.md`
- `descubrimiento/state.yaml`

## Estructura

- Lo que sabemos.
- Lo que no sabemos.
- Lo que queremos aprender.
- Contradicciones o tensiones.
- Lecturas del copiloto.
- Material crudo pendiente.

## Usar el template

En `base-conocimiento.md`, usar tablas con IDs:

- `S-*` para cosas que sabemos.
- `NS-*` para cosas que no sabemos.
- Supuestos que tambien deben pasar a `assumptions.md`.

No sintetizar prematuramente. Esta etapa ordena el terreno.

## Gate

Accion sugerida:

- `Avanzar` si hay preguntas claras para research.
- `Profundizar` si falta material o hay vaguedad.
- `Cuestionar` si se estan tratando supuestos como hechos.
- `Concilio` si las contradicciones definen el foco.
