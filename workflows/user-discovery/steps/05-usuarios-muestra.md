# 05, Usuarios y Muestra Cualitativa

## Objetivo

Definir a quien entrevistar y con que diversidad minima.

## Notas del método

- Preguntar quien es el usuario real, no solo quien compra.
- En logistica, por ejemplo, el usuario puede ser quien maneja la logistica en la empresa.
- Default cualitativo: 10-12 entrevistas cuando el scope lo justifique.
- No hace falta representatividad estadistica; hace falta diversidad para encontrar patrones.

## Documentos a tocar

- `descubrimiento/usuarios-y-muestra.md`
- `descubrimiento/state.yaml`
- `descubrimiento/assumptions.md`
- `descubrimiento/decision-log.md`

## Checklist de calidad

- Usuario foco definido.
- Otros perfiles relevantes identificados.
- Criterios de diversidad claros.
- Cantidad por perfil.
- Motivo de cada perfil.
- Diferencia usuario, cliente, pagador, decisor y operador.
- Incluye mainstream y extremos cuando aporta.
- Considera accesibilidad real para reclutar.

## Usar el template

Completar:

- Tabla usuario vs cliente.
- Segmentos posibles.
- Extremos y mainstream.
- Muestra recomendada.
- Plan de cobertura por pregunta de aprendizaje.

## Concilio

Sugerir `Concilio` si:

- Hay multiples stakeholders.
- No esta claro quien es usuario, comprador o influenciador.
- Hay marketplace o ecosistema de dos puntas.
- El target incluye pymes y no esta claro quien decide, quien opera y quien paga.

## Gate

Accion sugerida:

- `Avanzar` si la muestra es reclutable y responde al challenge.
- `Profundizar` si faltan perfiles o criterios.
- `Cuestionar` si se eligieron solo usuarios comodos/amigos.
