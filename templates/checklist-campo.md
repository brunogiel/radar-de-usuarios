# Checklist de Campo

Este documento evita improvisar entrevistas. Usarlo antes, durante y despues de cada salida a campo o llamada.

## Antes

### Preparacion de investigacion

- [ ] Design Challenge visible.
- [ ] Objetivos de aprendizaje claros.
- [ ] Perfil del entrevistado revisado.
- [ ] Guia correspondiente lista.
- [ ] Roles definidos: quien pregunta, quien toma notas, quien observa.
- [ ] Herramienta de grabacion o notas probada.
- [ ] Plan B si falla la tecnologia.

### Privacidad y consentimiento

- [ ] Explicar proposito sin vender ni sesgar.
- [ ] Pedir permiso para grabar.
- [ ] Pedir permiso para fotos si aplica.
- [ ] Evitar fotos de caras o informacion sensible si no hay permiso explicito.
- [ ] Aclarar si se usaran nombres reales o anonimos.

### Contexto

- [ ] Entrevistar en su entorno real si es posible.
- [ ] Preparar preguntas sobre objetos, documentos, espacios o herramientas.
- [ ] Si es presencial, llevar cuaderno, lapicera y bateria.

## Durante

- [ ] Arrancar con rapport.
- [ ] Recordar que el entrevistado es el experto.
- [ ] Hacer preguntas abiertas.
- [ ] Pedir ejemplos recientes.
- [ ] Preguntar por que.
- [ ] Pedir "mostrame" si hay objeto, documento o flujo.
- [ ] Registrar citas textuales.
- [ ] Observar entorno, body language, herramientas y workarounds.
- [ ] Dejar que la conversacion se desvie si aparece algo valioso.
- [ ] No juzgar.
- [ ] No corregir.
- [ ] No completar frases.
- [ ] No validar una solucion.

## Despues, dentro de las 24 horas

- [ ] Guardar audio/video/notas con fecha, perfil y nombre anonimo.
- [ ] Escribir 5-10 citas textuales fuertes.
- [ ] Escribir observaciones del entrevistador separadas de dichos del usuario.
- [ ] Anotar momentos de tension, sorpresa o emocion.
- [ ] Registrar preguntas nuevas.
- [ ] Actualizar tracker de reclutamiento.
- [ ] Marcar gaps de muestra.

## Nomenclatura sugerida

```text
YYYY-MM-DD_perfil_nombre-anonimo_tipo.md
```

Ejemplo:

```text
2026-05-11_pyme-logistica_e01_notas.md
```

## Errores a evitar

- Hacer preguntas cerradas.
- Inducir respuestas.
- Hablar mas que escuchar.
- Correr por la guia sin profundizar.
- Buscar que confirmen lo que queremos oir.
- Tratar expertos o benchmarks como sustituto de usuarios.
